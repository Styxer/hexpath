# hexpath Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build phase 1 of hexpath: a release-gated Python geo pipeline feeding PostGIS, and a Spring Boot read service offering place search, boundary lookup and route-aware search (PostGIS and H3 strategies, settled by benchmark), with tests, CI and operational docs.

**Architecture:** The Python pipeline validates and reconciles OpenStreetMap data in memory. It loads accepted releases into per-release partitions and activates them in one transaction that also writes an outbox event and sends a NOTIFY. The Spring Boot service connects read-only, pins each request to an immutable snapshot of the active release, and swaps snapshots when it hears the event. Both sides share one SQL migration set, one normalisation golden file, and one pipeline-generated test seed.

**Tech Stack:**
- Java 21 language level; CI runs JDK 21, 25 and Ofir's local version.
- Spring Boot 4.1.x, NamedParameterJdbcTemplate, JTS, h3-java 4.x, springdoc 3.x, Testcontainers, jqwik, openapi-diff.
- Python 3.10+: psycopg 3, shapely 2, h3 4.x, osm2geojson, httpx, pytest, testcontainers, openapi-core.
- PostGIS image `postgis/postgis:17-3.5`; GitHub Actions; Leaflet.

**Spec:** `docs/superpowers/specs/2026-11-16-geo-intelligence-showcase-design.md` (rev 2). Section references below (§) point there.

## Review Focus

1. **Swapped coordinates.** A client sends GeoJSON as [lat,lon]. In Tel Aviv that lands far outside coverage. Expected: **422 out-of-coverage**, never a 200 with an empty list. Test in Task 12.
2. **`gc` racing the service's snapshot swap.** A release retired moments ago is still pinned by the service. Querying a dropped partition returns zero rows **silently**. Expected: `gc` skips releases retired less than 10 minutes ago. Test in Task 6.
3. **A query empty after normalisation.** For example `q="רחוב"`, `q="St."` or `q="   "`. Expected: **400 invalid-parameter**, not a full scan or a 500. Test in Task 10.
4. **Degenerate routes.** One vertex, all vertices identical, or NaN or Infinity coordinates. Expected: **400 invalid-parameter**. Test in Task 12.
5. **A pagination cursor from an earlier release, or tampered with.** Expected: **400 invalid-parameter** whose detail says the cursor belongs to another release or is malformed. Never mixed-release pages, never a 500. Test in Task 10.

**Interfaces:**
- `fetch_overpass(bbox, out_path: Path, endpoint="https://overpass-api.de/api/interpreter") -> Path` writes the gzipped Overpass JSON response. The query uses `[out:json][timeout:180]` and selects within the bbox:
  - nodes and ways with `amenity`, `tourism` or `shop`;
  - nodes and ways with `addr:housenumber`;
  - ways with `highway~"^(trunk|primary|secondary|tertiary|unclassified|residential|living_street|service)$"`;

  - It ends with `out body geom;`.
- `transform(osm: dict, zones: dict, coverage) -> Dataset`:
  - Uses `osm2geojson.json2geojson` for relation polygons. Way POIs and addresses use the polygon centroid.
  - `source_timestamp` is taken from `osm["osm3s"]["timestamp_osm_base"]`.
  - Unnamed POIs and unmapped categories are counted in `dropped`, never silently lost.

### Task 5: Reconcile and gate

**Files:**
- Create: `reconcile.py`, `gate.py`
- Test: `tests/test_reconcile.py`, `tests/test_gate.py`

**Interfaces:**
- `Baseline(release_id:int, counts:dict[str,int], places:dict[str,tuple[float,float,str]], boundary_areas:dict[str,float])`. Places map id to `(lon, lat, normalized_name)`; areas are planar degree² (only ratios are used).
- `Thresholds(count_change_pct=10.0, moved_m=50.0, moved_share_pct=5.0, boundary_area_change_pct=20.0)`
- `ReconcileResult(bootstrap:bool, changes:dict, breaches:list[str])`.
  - `changes` has `added`, `removed`, `moved` and `renamed` per entity type, plus `boundary_area_change_pct` per boundary id.
  - Each breach is a human-readable string naming the metric and its value.
- `reconcile(ds, baseline: Baseline|None, t: Thresholds) -> ReconcileResult`. With no baseline, it returns `bootstrap=True` with no breaches.
- `Override(user:str, reason:str, at:datetime)`. `reason` must be non-empty after strip, or a `ValueError` is raised.
- `GateDecision(passed:bool, overridden:bool, reasons:list[str])`.
- `decide(findings, rec, override: Override|None) -> GateDecision`:

- Test: `tests/db/conftest.py`, `tests/db/test_schema.py`, `tests/db/test_store.py`, `tests/db/test_lock.py`, `tests/db/test_events.py`

**Interfaces:**
- `migrate(owner_dsn) -> int` applies the pending `db/migrations/V*.sql` files in order and returns the version.
- `require_schema(conn, expected=EXPECTED_SCHEMA_VERSION)` raises `SchemaMismatch(found, expected)`.
- `ReleaseStore(conn)` (connected as `geo_writer`):
  - `find_by_hash(h) -> int|None`
  - `load_baseline() -> Baseline|None`
  - `record_rejected(ds, report:dict) -> int`: inserts a status row only, with no partitions.
  - `stage(ds, report:dict, override:Override|None) -> int`:
    1. Calls `hexpath_create_partitions`.
    2. COPYs every entity into the parent tables. Geometries are written as EWKB hex, and `*_norm` columns are filled with `normalize`.
    3. Sets status STAGED, with `stats` = counts plus `coverage` [w,s,e,n] and `dropped`.
  - `publish(release_id)` runs as one transaction, in this order:
    1. Old ACTIVE becomes RETIRED, with `retired_at = now()`.
    2. The target becomes ACTIVE, with `published_at = now()`.
    3. Insert `dataset_event(type='RELEASE_ACTIVATED', payload={"release_id":id,"previous":old})`.
    4. `NOTIFY dataset_events, '<id>'`.
  - `rollback() -> int` does the same as publish, except that the current ACTIVE becomes **ROLLED_BACK** and the newest RETIRED becomes ACTIVE. It raises `NothingToRollBack` when there is no target.
  - `gc(keep_retired=2, grace=timedelta(minutes=10)) -> list[int]` drops the partitions of:
    - RETIRED releases beyond the newest `keep_retired`, but only those whose `retired_at < now() - grace`;
    - ROLLED_BACK releases whose `retired_at` is older than the grace period.
    - Release rows are kept.
- `pipeline_lock(conn)`: a context manager around `pg_try_advisory_lock(0x68657870)`. It raises `PipelineBusy` when the lock is held and releases it on exit.
- `OutboxRelay` (a Protocol) has one method, `send(event: dict) -> None`. `LoggingRelay` implements it. `relay_pending(conn, relay) -> int` sends the rows where `relayed_at IS NULL` in id order and sets `relayed_at`.

### Task 12: Route-aware (corridor) search, two strategies

**Files:**
- Create: `corridor/*`
- Test: `corridor/H3CoverPropertyTest.java`, `corridor/RouteInputTest.java`, `corridor/CorridorSearchIT.java`

**Interfaces:**
- `RouteInput.parse(JsonNode route) -> LineString` throws `INVALID_PARAMETER` for:
  - anything that isn't a GeoJSON LineString;
  - fewer than 2 **distinct** vertices;
  - non-finite coordinates;
  - more than 1000 vertices.
  - It throws `ROUTE_TOO_LONG` when the geodesic length is over 50 km.
  - The caller checks coverage on every vertex with `CoverageGuard`.
- `interface CorridorSearch { String name(); CorridorResult search(long releaseId, LineString route, double bufferM, String categoryOrNull, int limit); }`
- `record CorridorResult(List<CorridorHit> hits, int candidates)`; `record CorridorHit(Place place, double distanceM, double alongM)`.
- `PostgisCorridorSearch` (`name()="postgis"`):
  - Filter: `ST_DWithin(p.geom::geography, :route::geography, :buffer)`.
  - `distance_m = ST_Distance(p.geom::geography, :route::geography)`.
  - `along_m = ST_LineLocatePoint(:route, p.geom) * ST_Length(:route::geography)`.
  - Order `distance_m, id`. `candidates` = the number of rows that passed the filter.
- `H3Cover`:
  - `static double SPACING_M = H3Core.getHexagonEdgeLengthAvg(9, METERS) / 2`.
  - `static int ringSize(double bufferM) = (int) ceil((bufferM + SPACING_M) / (sqrt(3)/2 * edgeAvgM * 0.9)) + 1`.
  - `Set<Long> cover(LineString route, double bufferM)`: densify to ≤ `SPACING_M` geodesically, map vertices to r9 cells, then take the union of `gridDisk(cell, ringSize(bufferM))`.
- `H3CorridorSearch` (`name()="h3"`):
  1. Run `cover`.
  2. Select places with `h3_r9 = ANY(:cells)` for that release. `candidates` = that count.
  3. Apply the same exact distance filter and the same `distance_m` and `along_m` expressions as PostGIS, in the same SQL statement as a CTE.
  4. Order the same way.
- `POST /v1/search/along-route`:
  - Body `{"route": LineString, "buffer_m"?: number, "category"?: string, "limit"?: int}`; query `?strategy=postgis|h3` (hidden from the public docs) and `?debug=true`.
  - The default strategy comes from `hexpath.corridor.default-strategy` (initially `postgis`; Task 16 may change it).
  - Response: `{"strategy","results":[{...place fields..., "distance_m","along_m"}]}`. With `debug=true` it adds `"debug":{"candidates":int}`.
  - The `Server-Timing: corridor;dur=<ms>` header is always set.
- The `rank=detour` option is phase 2 and is not built here.
